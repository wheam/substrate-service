# 05 — Governed Agent Memory（受治理的 agent 记忆）：模式说明

> 一份能**单独读懂**的模式说明：这是什么、为什么这么设计、怎么落地。`substrate` 是它的开源参考实现。
> 命名约定：**模式**对外名暂用 **Governed Agent Memory / 受治理的 agent 记忆（GAM）**（临时，不纠结）；**项目/实现名**是 **`substrate`**。

---

## 一段式定义

**Governed Agent Memory** 是一种给「多个 AI agent 共享同一份长期个人/团队记忆」的记忆架构：

> 一切写入先落**隔离 inbox**（写路径无 LLM、秒回）→ 一个守门 agent（keeper）读它、但**只产出结构化的「决定」（JSON），从不亲手碰文件**→ 决定交给**确定性执行器**落盘 → 主人对某条的裁定被**自动立成判例**（下次同类照此判）→ 全部正典是 **markdown + git（文件即真相）**→ 治理逻辑**集中在服务端**（不靠每个 agent 自律）→ 每次读写、每次准入都**留痕、给人话理由**。

一句话对比：普通「记忆层」让 LLM 直接写你的库；GAM 把 **LLM 降级为「只出主意的顾问」**，真正的写入永远走一段可测、可回归、可审计的确定性管线——于是你能当自己记忆的**作者**，而不是被一堆 agent 悄悄改写。

---

## 四条特色

1. **受治理的写入（keeper 模式）** —— 能让你当「作者」的那个原子。所有写入过一道服务端强制的门（inbox → keeper 判断 → 执行器落盘），而不是任何 agent 想写就写。
2. **可带走的真相 / 主权** —— markdown + git 是**唯一**真相，索引等都是可重建的派生物。**主权 = 离线**：任一时刻 `git clone` 到本地即得一份完整、可读、可离线用的副本，不锁在任何服务里。
3. **agent 中立 + 服务端集中治理** —— 任意支持 MCP 的 agent（Claude Code / Codex / Hermes / 未来的）连上即得同一套读写与同一套规矩；治理不复制进每个客户端的「胖 skill」，只在服务端一处。
4. **可审计** —— 每次读写留痕、每次准入有一句人话理由（为什么归这里、为什么拒、为什么转人问）。

---

## 机制骨架（怎么落地）

一条写入从进门到入库，经过七道确定性的关口 + 一道抗注入闸：

1. **隔离 inbox（写路径无 LLM，秒回）** —— 捕获/保存先落一个隔离区，立即回执。token 泄露最坏是「收件箱进垃圾」，碰不到库本体；写路径不调 LLM，所以永远快、永远不被入参里的提示词带跑。
2. **LLM 只出「决定」** —— keeper 读 inbox 件，输出一份**结构化决定 JSON**（归哪个 zone、canonical 还是 candidate、还是拒、还是转人问 + 一句理由 + 置信度）。它的目标/动作只能取材料里的白名单值，**产不出「执行」本身**。
3. **确定性执行器（LLM 从不碰文件）** —— 决定交给一段普通代码执行：写文件、更新索引、跑 doctor 校验，出错就回滚。**LLM 永远不直接写盘**，所以爆炸半径被代码框死，且可被金标集回归。
4. **判例法（主人裁定自动立判例）** —— keeper 拿不准就转人；主人在对话里一句话裁定，这次纠正被**自动记成判例**，下次同类照此判。你的每一次拍板都是在给自己的记忆「标注品味」。
5. **文件即真相（markdown + git）** —— 正典只有 markdown + git；要紧信息（来源、置信、认知类型、分层）一律写进页面 frontmatter，索引只是加速、随时可删可重建。
6. **服务端集中治理 + 全程审计** —— 规矩（该存什么、该提示存、查无不编、敏感边界）由服务端下发与强制，不靠逐 agent 自律；每次读写、每次 auth、每次准入都进审计日志（含被拒来源）。
7. **主频道 agent（降认知触点）** —— 需要主人拍板的事（低置信、待定夺、新分区提议、每周维护提案），集中由**一个你已经在用的对话**（标记为主频道的那个 agent）主动浮出问你，你自然语言回一句即可，不用另开面板、不用记着去处理。

**抗注入闸 —— 进程内批准登记表。** inbox 文件活在 git 里，`git pull` 能把**伪造的「已批准」件**同步进来。所以「谁批过」不信文件里的任何字：keeper 只认**本进程内经唯一合法批准入口（主人裁定）真记过账**的批准（记账 token 绑定件的 id/裁定/决定/路径/正文指纹）。文件里裸的「owner 已批」一律不认——伪造件、以及「先合法批一版、再偷换正文」的攻击，token 一失配就被打回重判。认证票一次性，防「批过的旧票复燃」。这道闸把「`git pull` 进来的文件 = 对抗输入」这条威胁模型，贯彻到治理与删除这些高危路径。
>
> 诚实边界（别把抗注入吹成绝对）：残余的同主题 exploit 均需**私库 git 推送权限**——而握有该权限的 principal 本就能直接改库，故记为个人 alpha 的**已知限制**、不再深挖。

> 安全红线（贯穿全程）：**凭据/密钥永不落库**——命中即真拒，连隔离层都不进；待裁件的**正文（= 对抗输入）绝不进**任何提示面 / 指令 / 摘要，浮出提示只带 id/类型/计数。

## 与「capture-first」竞品的一句差异

同赛道有 capture-first 的记忆产品（如 gbrain）：先无脑收进来，再靠**后台夜里静默重写/合并**你的笔记来保持整洁。GAM 的分野是**审批式治理 vs 静默改**——GAM 的夜班养护（去重、合并薄页、断链）产出的是**提案**，走同一条裁决通路等你一句话批，**永不半夜静默改你的记忆**。对「要当自己记忆作者、要主权」的用户，静默改是恐怖故事，审批式治理才配这套哲学。

（这份文档只讲「模式是什么、怎么落地」；不做竞品沙盘/战略对比。）
