# 05 — Governed Agent Memory（受治理的 agent 记忆）：模式说明

> 一份能**单独读懂**的模式说明：这是什么、为什么这么设计、怎么落地。`substrate-service` 是它的 MCP 开源参考实现。
> 命名约定：**模式**对外名暂用 **Governed Agent Memory / 受治理的 agent 记忆（GAM）**；**实现名**是 **`substrate-service`**。

---

## 它解决什么（先讲价值）

你的上下文散在各个工具里，每个新 AI 都从零认识你；而你真攒起来的记忆还容易烂——没人维护地不断往里丢，几个月后就成了一堆没法用的东西。GAM 给你一份**所有 agent 共享的长期记忆**，它随着变大而自己保持有序（把新东西归到该去的地方，像一个不知疲倦的图书管理员），于是你可以放心地不停往里加、而它照样好用；它永远是可 `git clone` 带走的 markdown，不锁在任何服务里。

一个人用，「保持整洁」是便利；一个团队共享一份记忆时，它是「共享大脑」和「一潭沼泽」的分界——去重、厘清谁说的、标出过时与矛盾。**写入的人越多，这层治理越关键**，这也是 GAM 在团队场景比在个人场景更锋利的原因。

安全是这份价值的一部分、而非全部：因为落盘永远走确定性代码、模型只出主意，藏在内容里的 prompt 不能直接变成文件操作，风险被约束在可测的执行边界内。下面讲**怎么做到**。

---

## 一段式定义（怎么做到）

**Governed Agent Memory** 是一种给「多个 AI agent 共享同一份长期个人/团队记忆」的记忆架构：

> 一切写入先落**隔离 inbox**（写路径无 LLM、秒回）→ 一个守门 agent（keeper）读它、但**只产出结构化的「决定」（JSON），从不亲手碰文件**→ 决定交给**确定性执行器**落盘 → 主人对某条的裁定被**自动立成判例**（下次同类照此判）→ 全部正典是 **markdown + git（文件即真相）**→ 治理逻辑**集中在服务端**（不靠每个 agent 自律）→ 每次读写、每次准入都**留痕、给人话理由**。

一句话对比：普通「记忆层」让 LLM 直接写你的库；GAM 把 **LLM 降级为「只出主意的顾问」**，真正的写入永远走一段可测、可回归、可审计的确定性管线——于是你能当自己记忆的**作者**，而不是被一堆 agent 悄悄改写。

---

## 四条特色

1. **受治理的写入（keeper 模式）** —— 能让你当「作者」的那个原子。所有写入过一道服务端强制的门（inbox → keeper 判断 → 执行器落盘），而不是任何 agent 想写就写。
2. **可带走的真相 / 主权** —— markdown + git 是**唯一**真相，索引等都是可重建的派生物。**主权 = 离线**：任一时刻 `git clone` 到本地即得一份完整、可读、可离线用的副本，不锁在任何服务里。
3. **agent 中立 + 服务端集中治理** —— 任意支持 MCP 的 agent（Claude Code / Codex / Hermes / 未来的）连上即得同一套读写与同一套规矩；治理不复制进每个客户端的「胖 skill」，只在服务端一处。
4. **可审计** —— 每次读写留痕、每次准入有一句人话理由（为什么归这里、为什么拒、为什么转人问）。

---

## 机制骨架（怎么落地）

一条写入从进门到入库，经过七道确定性的关口 + 一道抗注入闸：

1. **隔离 inbox（写路径无 LLM，秒回）** —— 捕获/保存先落一个隔离区，立即回执。投递型 token 泄露的写入爆炸半径被限制为「收件箱进垃圾」，碰不到库本体；其它 token 每客户端独立、可单独吊销。写路径不调 LLM，所以不会被入参里的提示词带跑。
2. **LLM 只出「受限计划」** —— 入口先签发本件可用的 effects/zones；keeper 让 LLM 判断语义、输出结构化 JSON，但 `confidence` 只代表语义把握，不能扩权，也不能自动制造一个“请主人确认”。
3. **确定性 effect policy + 执行器（LLM 从不碰文件）** —— 代码逐项校验真实副作用：新建、追加、敏感区写、删除、结构变更各有独立能力。新建普通页是可逆的追加动作，直接执行；低置信无害件旁置为 candidate，但 forbidden/local-only 绝不被旁置逻辑翻成入库；模型越界先受约束重规划。临时故障有限退避，耗尽只发运维告警、不制造主人选择题；本地 commit 与远端同步状态分开记录。落盘、索引、doctor 和回滚都由普通代码完成。
4. **只把真决策交给人** —— 只有目标身份冲突、不可逆/结构动作缺授权、或没有安全回退时才 owner-held。主人裁定会自动记成判例；provider/doctor/git 故障进入重试态，篡改进入安全隔离，都不伪装成“待你定夺”。
5. **文件即真相（markdown + git）** —— 正典只有 markdown + git；要紧信息（来源、置信、认知类型、分层）一律写进页面 frontmatter，索引只是加速、随时可删可重建。
6. **服务端集中治理 + 全程审计** —— 规矩（该存什么、该提示存、查无不编、敏感边界）由服务端下发与强制，不靠逐 agent 自律；每次读写、每次 auth、每次准入都进审计日志（含被拒来源）。
7. **主频道 agent（降认知触点）** —— 真正需要主人拍板的事（目标冲突、新分区、删除/覆盖等结构选择）集中由**一个你已经在用的对话**主动浮出；低置信本身、模型坏输出和基础设施故障不会进入这个列表。

**抗注入闸 —— git 外 proof registry + 一次性批准。** inbox 文件活在 git 里，`git pull` 能同步伪造件，所以文件自报的身份、能力和“owner 已批”一律不可信。认证入口把整份执行信封（actor/ingress/capabilities/hint/正文/候选）做内容绑定，proof 与主人批准票存在 git 外并跨正常重启保留；任一字段被偷换即失配隔离。终态执行前先持久 claim 并留下 consumed tombstone，历史 inbox 不能复燃；可回滚的执行故障会连同原件恢复同一份绑定计划，不交回 LLM 改判。
>
> 诚实边界（别把抗注入吹成绝对）：残余的同主题 exploit 均需**私库 git 推送权限**——而握有该权限的 principal 本就能直接改库，故记为个人 alpha 的**已知限制**、不再深挖。

> 安全红线（贯穿全程）：**凭据/密钥永不落库**——命中即真拒，连隔离层都不进；待裁件的**正文（= 对抗输入）绝不进**任何提示面 / 指令 / 摘要，浮出提示只带 id/类型/计数。

## 与「capture-first」竞品的一句差异

同赛道有 capture-first 的记忆产品（如 gbrain）：先无脑收进来，再靠后台静默重写/合并来保持整洁。GAM 的分野是**按副作用治理**：可逆、幂等、追加型动作自动做，删除/覆盖/结构塑形才需要主人批准；夜班可自动降级候选、记录报告，但不会静默做不可逆合并。它减少打扰，同时保留“主人是自己记忆作者”的边界。

## 参考实现

`substrate-service`（本仓库）是 GAM 的 MCP 开源参考实现：MCP server + keeper 守门 agent + 捕获端点，持有并唯一维护一份 markdown+git 的知识库实例。

参考实现另提供一个默认关闭的[个人轻治理档](07-light-governance.md)：少数 owner 明确信任的 high 客户端，可对明确普通页走确定性 create/append；歧义、高风险与结构动作仍保留上述 GAM 门禁。这是个人部署的成本调节器，不改变严格 GAM 模式本身，也不向 capture/低信任入口放权。
